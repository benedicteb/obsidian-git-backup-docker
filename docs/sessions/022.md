# Session 022 — Configurable Sync Mode

**Date**: 2026-11-26

## What was accomplished

Reviewed and finished the `feat/sync-mode-env-var` branch, which adds
`OBSIDIAN_GIT_SYNC_MODE` (`bidirectional` | `pull-only` | `mirror-remote`),
passed to `ob sync-config --mode` on every start.

- Ran a code review against `main` and addressed the findings.
- Verified in the obsidian-headless 0.0.14 package that `--mode` and all
  three values exist, and what each mode does with local changes.
- Briefly switched the default to `pull-only`, then reverted to
  `bidirectional` so existing installs behave the same.
- Moved the sync mode comment into the Dockerfile's sync section header and
  updated the `.env.example` section intro.
- Corrected the docs: the container's own `git pull` writes into `/vault`,
  which matters for both `bidirectional` and `mirror-remote`.
- Rewrote the branch history into four conventional commits so the release
  workflow computes a minor bump (v5.3.0) and accurate release notes.
- Drafted release notes (to be pasted into the GitHub Release by hand).

## Decisions made

See [ADR-0021](../adr/0021-configurable-sync-mode.md).

- Default stays `bidirectional` (no behaviour change on upgrade).
- Strict validation: no whitespace/case normalization; invalid values fail
  startup. This keeps the earlier expert-review decision.
- Minor version bump, not major: unset variable means identical stored
  config (`--mode bidirectional` deletes the stored `syncMode` key).

### Obsidian expert
- `pull-only` overwrites local copies when a file changes on Obsidian Sync,
  including git-side edits — **addressed** in docs and ADR.
- `mirror-remote` only acts on files within the sync filter — **addressed**.
- Confirmed from the 0.0.14 source that `mirror-remote` never touches
  `.git/`, `.gitignore` or `.gitattributes` (dot-paths are skipped by the
  local scan and rejected by the filter).

## Testing on a real node (Unraid)

- Variable unset: init, stored config and running sync all report
  `bidirectional`.
- `pull-only`: first attempt appeared not to work. `docker inspect` showed
  the Unraid key had a leading space (` OBSIDIAN_GIT_SYNC_MODE`), a separate
  variable. After fixing the key, everything reported `pull-only`.

Not yet tested on a node: that `pull-only` really stops uploads, invalid
values, and `mirror-remote` (the dotfile safety is confirmed from source
only).
