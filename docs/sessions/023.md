# Session 023 — Persist obsidian-headless State

**Date**: 2026-11-26

## What was accomplished

Follow-up from session 022: obsidian-headless state lived in the
container's home directory, so every container recreation caused a full
re-check and a new device name in Obsidian Sync.

- Investigated obsidian-headless 0.0.14's storage layout (`auth_token`,
  `sync/<vault-id>/{config.json,state.db,sync.log}`) and confirmed that
  `ob sync-setup` keeps `state.db`.
- Persist state under `/config/headless/<vault name>/` via
  `XDG_CONFIG_HOME`, set by a shared `headless-env.sh`.
- Remove stale vault configs after `sync-setup`.
- Reset sync state when `/vault` was re-cloned or replaced (marker in
  `.git`), so missing files aren't uploaded as deletions.
- Discard the unrotated `sync.log`.
- New `OBSIDIAN_GIT_DEVICE_NAME`, default `obsidian-git-backup (<vault>)`.
- Docs: README (env table, `/config` contents, shared config), `.env.example`,
  Dockerfile, Unraid template.

Also in this session, after merging PR #3: released v5.3.0 with
hand-written notes, and deleted the merged/obsolete branches on GitHub.

## Decisions made

See [ADR-0022](../adr/0022-persist-obsidian-headless-state.md).

- Per-vault state directories, because containers may share `/config`
  and ob looks configs up by path (`/vault` everywhere).
- Device name gets an env var with a stable default (maintainer's choice).

## Subagent reviews

### Linux expert
- Picking the current config by mtime could delete the real one (clock
  skew, restored `/config`) — **addressed**: remove all configs before
  sync-setup, prune directories without one afterwards.
- Non-ASCII vault names collide after per-byte `tr` — **addressed** with a
  checksum suffix.
- Root `rm -rf` in a user-writable tree — **addressed** (runs as obsidian).
- SQLite WAL on network/FUSE filesystems — **addressed** in docs.
- chmod failing on CIFS — **addressed** (warning instead of abort).
- Drop `cat |` before tee — **addressed**.

### UX designer
- Unraid Config Storage description, friendlier reset log message, how to
  run `ob` by hand, sanitized path note, device-name change explanation —
  **all addressed**.

### Obsidian expert
- Verified the ADR's claims against obsidian-headless 0.0.14.
- Files deleted while stopped would be deleted on Obsidian Sync —
  **addressed** (reset on `git ls-files --deleted`).
- No state.db migrations across ob versions — **addressed** (reset on
  version change).
- WAL on Unraid `/mnt/user` — **addressed** in docs and template.
- Restoring an older copy of the same clone isn't detected — documented.
- Matching the vault ID from `sync-setup --json` instead of the
  config-file approach — not needed after the Linux expert's fix.

## Testing

Logic tested in isolation: vault-name sanitizing, stale-config pruning
(including a stale config with a future mtime), and eight state-reset
scenarios (upgrade, restart, ob version change, missing tracked file,
re-clone). Not yet tested in a real container.
