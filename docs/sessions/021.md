# Session 021 — Datadog Metrics and Release Events

**Date**: 2026-03-16

## What was accomplished

Added Datadog integration to two GitHub Actions workflows:

1. **Daily pull count metric** — the existing `metrics.yml` workflow
   now also pushes the Docker Hub pull count as a gauge metric to
   Datadog EU1 via the v1 series API.

2. **Release event markers** — the `docker-publish.yml` workflow now
   posts a Datadog event after each GitHub Release. Events appear as
   vertical overlay markers on dashboard graphs, enabling visual
   correlation between releases and pull count trends.

### Changes made

1. **`.github/workflows/metrics.yml`** — Added a "Push metric to
   Datadog" step between the fetch/record step and the commit/push
   step. The step:
   - Skips gracefully when `DD_API_KEY` is not configured
   - Uses `printf %d` for JSON construction (injection-safe)
   - Handles network failures (HTTP 000/empty) without crashing
   - Provides actionable error messages for HTTP 403 specifically
   - Never fails the workflow — all errors produce warnings only

2. **`.github/workflows/docker-publish.yml`** — Added a "Post release
   event to Datadog" step after the GitHub Release creation. The event
   includes the version tag, a link to the release, and tags for
   dashboard filtering. Same optional/failure-tolerant pattern.

3. **`docs/adr/0020-datadog-metrics-push.md`** — Architecture decision
   record documenting both the metrics and events integration, EU1
   hardcoding rationale, and security considerations.

## Decisions made

- **Datadog region**: EU1 hardcoded (user's explicit choice). No
  `DD_SITE` variable — a deliberate simplicity trade-off for a
  single-maintainer project.
- **Metric name**: `obsidian_git_backup.docker_pulls` — namespaced
  under the project name.
- **Metric type**: `gauge` — appropriate for a cumulative counter
  where we report the absolute value.
- **Optional behavior**: The step is skipped if `DD_API_KEY` is not
  set. Forks and contributors are unaffected.

## Setup required

To enable both the metric and the release events, add one GitHub secret:
- **Name**: `DD_API_KEY`
- **Value**: A Datadog API key from Organization Settings > API Keys
  (EU1 console). The same key is used by both workflows — Datadog API
  keys have write access to both metrics and events endpoints.
